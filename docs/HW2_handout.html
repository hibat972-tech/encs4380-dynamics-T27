Likely questions, short answers

  1. P leaves an error? Holding the output needs u = Kp·e ≠ 0, so e ≠ 0: ess = 1/(1+K·Kp).
  2. I removes it? The integral keeps changing u until e = 0. It has memory, so it can overshoot.
  3. What does D do? Damps a plant that rings (2nd order). On a 1st-order plant the loop is (τ+K·Kd)s²+…: extra inertia, can raise overshoot.
  4. Why D on the measurement (P1/P2)? Same as de/dt for a constant setpoint, no spike at a setpoint step. P3 uses the assignment equation (on e), so the first sample has a kick.
  5. Slow sensor rings? Controller acts on old data (phase lag). PI + 1st-order plant is stable only if (τ+τs)(1+K·Kp) > τ·τs·K·Ki.
  6. Why RK4? Accurate for a larger step; h = 0.25/λ. Tests match closed forms to ~10⁻¹².
  1. Step vs Ts? Controller runs every Ts and holds u (ZOH); the plant is integrated with smaller sub-steps h = Ts/n.
  2. Large Ts breaks it? Hold adds ≈ Ts/2 delay. For K = 1, τ = 1, Kp = 9 stable only if Ts < τ·ln((1+K·Kp)/(K·Kp−1)) = 0.223 s.
  3. Windup / anti-windup? Integral grows while u is saturated. Ours stops adding to the sum while saturated and the error pushes further into the limit.
  4. K and τ of the motor? PWM step from rest, log encoder speed: K = Δspeed/ΔPWM, τ = time to 63.2%.
  5. PI design? ωn = 4/(ζ·ts), Kp = (2ζτωn−1)/K, Ki = τωn²/K. PI's zero adds overshoot, so the simulation judges.
  6. Saturation off in check 1? Kp = 9 gives u(0+) = 9; a 0–1 limit would clip it and break the linear formulas.
  7. Z-N on the motor? A 1st-order loop is stable for every Kp: no Ku. Needs 3 lags. Simulation only.
