Validation checks

Before trusting the PID toolkit, it has to reproduce three results for the plant \(G(s)=K/(\tau s+1)\) with \(K=1\) and \(\tau=1\) s. Each check below runs the closed-loop RK4 simulation when the page loads and compares what it measures with the formulas from the assignment.

How a check passes

  • Expected comes from the formulas in the assignment. Actual is measured on the simulated response: read off the curve (63.2% point, slope of a log plot, final value), from the eigenvalues of the closed-loop state matrix, or compared point by point with an exact solution.
  • Deviation is actual minus expected. A row passes when |deviation| ≤ its tolerance. A test passes only if every row passes.
  • Tolerances are small: 2% on a time constant, 0.05 percentage points on a steady-state error, 0.001 on ωn and ζ, and 10⁻⁴ on a curve compared with its exact solution. The RK4 step is chosen so the method error is far below these, so the tolerance covers read-off error only.
  • No control limit. With Kp = 9 the first control value is u = 9. A realistic limit would clip it, and the loop would no longer be the linear loop the formulas describe. The last row of Test 1 shows what a 0 to 1 limit would do.
  • Nothing is typed in as passing. Change the controller in js/pid-sim.js and the affected checks turn to Fail. The same checks run from the command line with npm test.
