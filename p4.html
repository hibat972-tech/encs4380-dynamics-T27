Tuning challenge

A hidden plant and a specification. You only get Kp, Ki and Kd. Tune the controller until every requirement says PASS. The plant is drawn at random from the same family as “Guess the sensor” in Homework 1 (first order, or second order that rings), and the specification is generated so that it can be met.

How to tune it

A recipe that works

  1. Run the open-loop step test (u = 1). Read the final value (that is K) and the time to 63% (that is τ), like in Homework 1.
  2. P first. Raise Kp until the response is fast enough. A steady-state error will remain.
  3. Add I until the error disappears. If the overshoot is too large, lower Ki.
  4. Add D only if the response rings.

How each requirement is judged

Overshoot: peak above the final value, in %. Settling time: the last time the output is outside ±2% of the final value. Steady-state error: \(|r-y_\infty|\) as a % of the setpoint; “zero” is accepted up to 1% because the simulation has finite length. A response that never settles fails the last two.

Scoring

Overshoot 30 points, settling time 40 points, steady-state error 30 points. Each part is all-or-nothing and judged on its own, so you can see exactly which one to fix.
